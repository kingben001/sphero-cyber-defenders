Pause the Click.

Learn how phishing tricks people, then program a Sphero BOLT to model the safe response: Stop, Check, Tell.

The goal

Students should leave knowing three things.

1 · Identify

What phishing is

A fake message designed to trick someone into clicking, sharing information, sending money, or downloading something unsafe.

2 · Predict

What a click can cause

A fake login page, stolen password, account takeover, exposed private information, malware, or money loss.

3 · Respond

What to do next

Stop. Check through a trusted source. Tell a trusted adult or use the approved reporting process.

Warm-up

Has anyone heard of phishing?

You can answer yes, no, or “I’m not sure.”

Phishing is something we can learn to spot. No one has to share a personal story.

What is phishing?

A fake message with a real goal.

Phishing is when someone pretends to be trustworthy to trick you into clicking, sharing information, sending money, or downloading something unsafe.

FakeIt may look like a school, game, friend, or company.
TrickyIt creates urgency, excitement, or fear.
GoalIt wants information or an unsafe action.

Required robot activity · 14 minutes

Exercise 3: Stop, Verify, Report

This is the main BOLT activity. It is intentionally simple enough to build in Sphero Edu without custom functions or a complicated detector.

Use the language students will remember:Stop = pause your hands. Check = look for evidence. Tell = report to a trusted adult or approved system.

Materials

One team needs

Robot

One charged BOLT and one device with Sphero Edu.

Cards

Two fictional message cards from Printables. Never use real accounts, passwords, or student information.

Workspace

A desk or parking mat. Rolling is not required; color is the signal.

Facilitator model

Say this first

“Your BOLT is going to be a cyber-alert robot. It is not deciding whether a message is safe. It is reminding us to use the safe sequence: Stop, Check, Tell.”

“The colors are our memory tool: blue means Stop, yellow means Check, and green means Tell.”

Build it

Basic block sequence

Block names can vary slightly by app version. Look for the closest visible block.

When Program Starts→Set Main LED to Blue→Wait / Delay 2 sec→Set Main LED to Yellow→Wait / Delay 2 sec→Set Main LED to Green→Stop / End

If you cannot find a text-display block: skip it. The colored LEDs are enough. Put the words STOP, CHECK, and TELL on paper where students can see them.

If you cannot find Wait/Delay: place the three color blocks in order and have the partner say each word as the color changes.

Run the activity

Exact instructions

Step 1 · 2 min

Assign roles

  • Coder: places the blocks.
  • Reader: reads the fictional message.
  • Checker: listens for two clues and watches the BOLT.
  • If there are fewer than three students, combine Checker with Reader.
Step 2 · 3 min

Build and run

  1. Build the sequence above.
  2. Run it once without a message.
  3. Ask: “What does each color mean?”
  4. Fix the order if the colors do not match the words.
Step 3 · 4 min

Round 1: spot the clues

  1. Reader shows Card A.
  2. Everyone silently finds clues.
  3. Reader says two clues aloud.
  4. Run the BOLT and say Stop, Check, Tell with it.
Step 4 · 4 min

Round 2: change roles

  1. Swap roles and use Card B.
  2. Before touching the robot, answer: “What should we do before clicking?”
  3. Run the sequence.
  4. Explain one possible consequence of clicking.

Debrief · 2 minutes

Ask these questions

Evidence

“What two clues made you slow down?”

Consequence

“What might a fake link lead to?”

Response

“Who could you tell at school or at home?”

Key correction to make aloud: “The robot is an analogy. It can show a programmed alert, but it cannot decide a person’s intent or prove that a message is safe. A human still checks the evidence.”

Optional Exercise 4 · 8 minutes

Code the Phishing Detector.

Use this only after Exercise 3 is complete. Do not use it as part of the exit ticket.

Time rule:If teams are still building Exercise 3, skip this page. Students can meet the lesson goal without it.

Simplified challenge

Turn clues into a choice.

Student rule

Count the warning clues on a message:

  • Urgency
  • Unexpected prize
  • Password or personal-data request
  • Odd sender or link

Two or more clues: show red “PHISH?”
Fewer than two: show yellow “CHECK.”

Teacher model

Start→Set clues = 2→If clues ≥ 2→Red alert
Else→Yellow: Check

This is a way to explain the algorithm, not a promise that every editor will use these exact block names.

If the blocks are available

Exact student directions

  1. Create a number variable named clues.
  2. Set clues to 2 for the sample message.
  3. Add an if / then / else block.
  4. Condition: clues is greater than or equal to 2.
  5. Then: set the Main LED to red and display “PHISH?” if a display block is available.
  6. Else: set the Main LED to yellow and display “CHECK.”
  7. Change the number to 0, 1, 2, and 3. Predict the color, run it, and explain the result.

If the blocks are missing

No-variable fallback

Make two short programs instead:

Program A→Red = PHISH?
Program B→Yellow = CHECK

Students manually choose Program A when they count two or more clues and Program B when they count fewer. The thinking is the same; the code is simpler.

Do not add this to the exit ticket. The exit ticket checks phishing knowledge and the safe response, so every student can complete it even if this extension is skipped.

Teacher answer key

1. A fake message that tries to trick someone into clicking, sharing information, sending money, or downloading something unsafe.

2. Any two: urgency, unexpected prize, password/personal-data request, odd sender/link, unexpected attachment.

3. Possible consequences include a fake login page, stolen password, account takeover, exposed private information, malware, or money loss. Safe response: Stop, Check through a trusted source, and Tell/report to a trusted adult or approved school process.
